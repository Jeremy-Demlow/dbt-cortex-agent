# Security Policy

## Supported versions

Security fixes are considered on a best-effort basis for the latest released version and the
current default branch. Older versions and forks are unsupported. There is no response or
remediation SLA.

## Private reporting and coordinated disclosure

Do not open a public issue. Use this repository's GitHub private vulnerability
reporting form and include the affected version, impact, reproduction, and
mitigation. Remove credentials, customer data, account identifiers, private
URLs, query results, and confidential information; use synthetic data. Do not
send secrets. Request an approved secure-transfer method first if needed.

Allow a reasonable opportunity for validation and coordinated disclosure. Maintainers will
coordinate scope, remediation, attribution, and disclosure when practical but promise no
timeline. Do not access systems or data beyond your authorization.

This is an independent project process, not Snowflake support. Snowflake product
or service vulnerabilities must use Snowflake's official reporting processes.
